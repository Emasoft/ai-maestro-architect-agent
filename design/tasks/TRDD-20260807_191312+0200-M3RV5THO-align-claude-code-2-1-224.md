## The defect

Claude Code **2.1.218**: *"Changed skills with `context: fork` to run in the
background by default; opt out per skill with `background: false`."*

26 of AMAA's 27 skills carry `context: fork`; none carried `background:`. Every
one of them is a synchronous consult — the body says "identify the pattern →
consult the reference doc → follow the protocol", and the main agent's workflow
consumes that result inline before the next step. Background-by-default turns
each into fire-and-forget: the caller receives an agent name, proceeds without an
answer, and nothing reports an error.

`amaa-github-integration` is the only `user-invocable: true` skill, so it is the
most visible symptom: a user typing the skill name gets a backgrounded job rather
than the integration guidance they asked for.

## What was decided

**Restore synchronous semantics now; defer selective async to its own task.**
Adopting `background: true` for a genuinely long-running skill (api-research,
cicd-design, modularization) is not a frontmatter tweak — it requires rewriting
the caller's `[DONE]`/ACK completion protocol in
`amaa-design-communication-patterns`, which is a design change against the fleet's
async-completion semantics. That work is deliberately NOT in this TRDD.

**Self-impose a one-layer delegation ceiling.** CC 2.1.217 disabled nesting,
2.1.219 re-enabled it at depth 3, and 2.1.224 removed the per-session spawn cap
(concurrency still caps at 20). AMAA does not use the headroom: its five bundled
sub-agents execute and return. The routing table stays the single delegation
layer. Cheap — the routing was already one layer — and it keeps AMAA from
generating concurrent subagent start/stop traffic that fleet-side counters are
not yet hardened against.

**Keep AMP as the governed channel; treat native inbound as untrusted.** Verified
version history and the full policy live in
`skills/amaa-design-communication-patterns/references/native-cross-session-channel.md`.

> **Superseding note (2026-08-07T19:52):** this was first read as "AMAA is the
> outlier". It is not. A complete fleet sweep (**8 of 8**) found **four**
> conventions — `opus` ×4 (assistant-manager, chief-of-staff, orchestrator,
> integrator), no key ×2 (AMAA + programmer), `inherit` ×1 (maintainer),
> `sonnet` ×1 (autonomous). So **exactly half** the fleet follows RP-MODEL-01's
> "Every shipped role-plugin PINS `model: opus`", which is **false as written** —
> and the SPEC's own *mandatory* `ai-maestro-autonomous-agent` (RP-TITLES-02)
> pins `sonnet`. TRDD-TYB3Q1NJ was reframed accordingly before any approver saw
> it.

**The gap is NOT being closed in this TRDD, on purpose.** Four reasons, and any
one of them alone would justify waiting:

1. **The spec flags the rule as unresolved against itself.** RP-MODEL-01's own
   text says it "contradicts the general 'omit `model:`, inherit session'
   guidance (CLAUDE.md distillation / CPV CA-04)" and is "Recorded as a live
   inconsistency, **not resolved**".
2. **It says SHOULD, and scopes it to new plugins** — "a **new** role-plugin
   SHOULD copy the pattern". AMAA is an existing shipped plugin.
3. **The spec's own validation checklist does not require it.** RP-VAL-01…07
   contains no main-agent model-pin check; RP-VAL-06 constrains only subagents,
   and AMAA passes that.
4. **It collides with the gate that guards AMAA's release.** CPV's CA-04
   cache-warmth invariant treats an unpinned agent as correct; pinning would put
   the publish pipeline and the spec in direct conflict.

Choosing between two authorities that openly contradict each other is not a
Tier-0 self-authorization — it is exactly the "architectural / first-of-kind"
shape that routes to MANAGER via AMCOS. **Route it, do not decide it.** Note also
that CC 2.1.219 made Opus 5 (1M context) the default Opus, so `model: opus` now
resolves differently than when the pattern was established — whoever rules on
this should rule on the current meaning, not the historical one.
