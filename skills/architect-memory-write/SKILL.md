# Architect Memory Write

## Overview

Captures one durable fact as a schema-valid markdown memory note and appends
its line to the `MEMORY.md` index. The note's `description` MUST carry the
SYMPTOM vocabulary a future session will search with (the question, the
user's words, the error text) — never the answer's jargon. See
`rules/memory-protocol.md` for the index-by-the-question law.

## Prerequisites

- Write access to the memory directory (default:
  `$HOME/.claude/projects/<project-slug>/memory`).

## Instructions

1. Distill exactly ONE fact worth remembering: a design decision + rationale,
   a rejected alternative + why, a user-stated constraint, a gotcha that cost
   time. Skip anything derivable from the repo or design documents.
2. Compose the `description` from the SYMPTOM side: what would a future
   session type when this recurs? Put the ANSWER in the body.
3. Pick the note `type`: `user` (who the user is), `feedback` (guidance on
   how to work), `project` (ongoing work/constraints), `reference` (external
   pointers). For `feedback`/`project`, include `**Why:**` and
   `**How to apply:**` lines in the body.
4. Run the writer script:

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/skills/architect-memory-write/scripts/write_note.py" \
     --memdir "$MEMDIR" \
     --name "kebab-case-slug" \
     --description "symptom-side summary a future search will hit" \
     --type project \
     --title "Human Title" \
     --body "The one fact. **Why:** ... **How to apply:** ..."
   ```

5. Verify the script's confirmation line, which echoes the note path and the
   index line it appended.

## Output

Creates `<memdir>/<name>.md` with valid frontmatter
(`name`, `description`, `metadata.node_type: memory`, `metadata.type`) and
appends one index line to `<memdir>/MEMORY.md` — a markdown link from the
note's title to its filename, followed by an em-dash and the description
hook (creating the index file if missing). Refuses to overwrite an
existing note.

## Error Handling

- Existing note with the same name → exits 1 with `note exists` (update by
  editing the file directly, or pick a new name; never silently overwrite).
- Invalid name (not kebab-case) or empty description → exits 2 with the
  specific validation error. Fail fast; no partial writes.

## Examples

```text
User: remember this — the orchestrator rejects handoffs without acceptance criteria
User: save a memory note about why we rejected GraphQL for the inventory API
User: /architect-memory-write the design index must never be regenerated by hand
```
